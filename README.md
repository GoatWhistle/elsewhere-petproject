# Elsewhere

Планировщик путешествий, который начинается не с города и дат, а с описания поездки, которую человек хочет
прожить.

Вместо привычного «выбрать направление → даты → фильтры → сотни отелей → отзывы → бронь» пользователь пишет
одну фразу — «вдвоём на неделю к морю, до €1800, спокойно, тепло, вкусно есть и много гулять» — и получает
несколько осмысленно разных вариантов поездки с объяснением компромиссов, возможностью подвинуть любой параметр
и увидеть риски до того, как что-то решено.

```
Мечта → Futures → Симуляция → Прогноз → План
```

Мы ничего не бронируем и не берём денег. Результат — план поездки с оценкой стоимости.

## Что делает система

| Механика | Что происходит |
|---|---|
| **Travel DNA** | Свободный текст превращается в закрытый набор измерений с весами. Пользователь может править их руками |
| **Futures** | Три намеренно разных сценария поездки — не топ-3 по одному баллу, а разные архетипы. Если разных всего два, система говорит об этом, а не добивает третий |
| **Experience Match** | Процент совпадения с разбором по измерениям. Без вкладов процент не показывается |
| **Future Simulator** | «Дешевле», «спокойнее», «ближе к морю» — ползунком или фразой. Пересчёт даёт новую версию поездки и дельту, где числа сходятся |
| **Forecast** | Риски именно для этого человека, каждый с измерением под ним и свежестью данных. Чего не проверили — сказано отдельно |
| **Trip Plan** | Перелёт, проживание, трансферы, общая стоимость с происхождением каждой суммы |

## Принципы, на которых это держится

Это не стилевые предпочтения — каждый пункт закрывает конкретный способ сломать продукт.

**Модель читает язык и пишет язык, но никогда не владеет числом.** LLM разбирает фразу в закрытый словарь,
переводит инструкцию в набор корректировок и пишет текст поверх уже посчитанного. Все баллы, цены, расстояния и
дельты считаются детерминированно.

**Ничто важное не является голым числом.** Балл совпадения требует вкладов по измерениям. Риск требует
доказательства с датой. Компонент цены требует признака происхождения: `estimate` — наблюдаемая рыночная цена,
`modeled` — сгенерированная нами.

**Неопределённость — это данные, а не пустота.** Если модель не ответила, вызов возвращает признак деградации, и
пользователю говорят об этом. Непроверенное измерение не засчитывается как нейтральное.

**Ровно одно число в продукте синтетическое — цена номера.** Её основа — наблюдаемый ценовой уровень объекта,
но сезонность смоделирована из климата и популярности. Это гипотеза, а не измерение, и она помечена как
`modeled` везде, где появляется. Тарифы, расстояния и погода — наблюдаемые.

**Futures неизменяемы.** Симуляция создаёт новую версию с ссылкой на родителя и дельтой, а не правит старую.

## Источники данных

| Что | Откуда | Природа |
|---|---|---|
| Каталог объектов размещения | разовый сбор, хранится локально | реальные |
| География: берег, дороги, POI, аэропорты | выгрузка OSM в PostGIS | реальные |
| Климат и погода | Open-Meteo | реальные |
| Авиатарифы | Ignav | реальные, живые |
| Цена номера на даты | собственная модель | **синтетика** |
| Отзывы | источника не существует | отсутствуют |

Корпус: 7 направлений, 408 объектов — Анапа, Сочи, Калининград, Казань, Санкт-Петербург, Кавказские Минеральные
Воды, Шерегеш. Три города, два моря, две горы: без разброса по географии выбор из трёх разных вариантов
невозможен.

## Стек

Ruby 3.3.6, Rails 8.1, модульный монолит с границами на packwerk. PostgreSQL с PostGIS, Redis и Sidekiq.
Фронтенд на React и TypeScript, клиент генерируется из контракта OpenAPI, моки на MSW. Обращение к LLM идёт
через OpenAI-совместимый эндпоинт — локально это Ollama или LM Studio, модель задаётся конфигурацией.

Ни брокера сообщений, ни микросервисов, ни векторного хранилища: под них пока нет требования.

## Структура

```
packs/
  shared/       значимые объекты, запуск задач к модели
  supply/       единственный выход во внешний мир: тарифы, климат, география, сбор каталога, модель цены
  planning/     разбор мечты, Travel DNA, ограничения, совпадение, разнообразие, сборка, симулятор
  foresight/    доказательства, правила рисков, релевантность, оценка, смягчения
app/            контроллеры и фоновые задачи, вся логика в пакетах
web/            фронтенд
docs/           продукт, архитектура, исследования, контракты, решения
spec/           тесты, включая набор из десяти персон и проверку соответствия контракту
```

Зависимости направлены в одну сторону: `shared ← supply ← planning ← foresight`. Пакет читает только свои
таблицы, наружу ходит только `supply`, packwerk это проверяет.

## Запуск

```bash
bin/setup
```

Ставит зависимости, готовит базу и включает git-хуки. Если на машине нет Ruby 3.3, переключается на Docker сам.

```bash
bin/rails server
```

Фронтенд отдельно:

```bash
npm install --prefix web && npm run dev --prefix web
```

Через Docker целиком:

```bash
docker compose up
```

API поднимается на `localhost:3000`, фронтенд — на `localhost:5173`.

### Настройки

Копия `.env.example` создаётся автоматически. Что стоит знать:

- `SUPPLY_MODE` — `fixture` по умолчанию, всё работает без единого внешнего ключа. `live` включает реальных
  поставщиков и требует `IGNAV_API_KEY` и `ORS_API_KEY`;
- `LLM_BASE_URL` и `LLM_MODEL` — по умолчанию рассчитаны на локальную Ollama с `qwen3:8b`. Без работающей
  модели система не падает: каждый вызов имеет детерминированный запасной путь и честно сообщает о деградации;
- `LLM_TIMEOUT_SECONDS` — 120. Локальная `qwen3:8b` разбирает мечту около 31 секунды, поэтому маленький таймаут
  выглядит как ненастроенная модель.

## Проверки

```bash
bin/check
```

Один вызов: границы packwerk, 248 примеров RSpec, проверка типов и линтер фронтенда. CI намеренно нет — вместо
него pre-push хук, который запускает то же самое перед отправкой.

Тесты фронтенда отдельно:

```bash
npm test --prefix web
```

52 теста в 9 файлах.

Главный тест продукта — набор персон: десять описаний поездки проходят весь путь от создания сессии до плана
через HTTP. Изменение в логике совпадения, не прогнанное через них, нельзя считать законченным.

## Что известно и что нет

Сборка завершена, набор тестов зелёный. Незакрытыми остаются две проверки, и обе честнее назвать вслух.

Модель ни разу не измеряли на наборе персон. У каждого обращения к LLM есть детерминированный запасной путь,
поэтому зелёные тесты не доказывают, что модель делает свою работу — они доказывают, что система работает и без
неё.

Живой прогон в режиме `SUPPLY_MODE=live` был и не прошёл: Ignav ответил `401` на все запросы, живых тарифов
получено ноль, генерация вернула отказ. Это ошибка аутентификации, а не отсутствие маршрутов, но полный путь в
живом режиме пока не пройден.
