# Подтверждённые исследования

Здесь остаются только выводы, которые объясняют действующие решения. Хронология проб, промежуточные ошибки и
данные конкретных локальных запусков удалены: это диагностика, а не документация продукта.

## Каталог объектов и цены проживания

Проверялись Yandex Travel Partner API, Travelpayouts/Hotellook, RateHawk, Ostrovok B2B, Bronevik, Amadeus и
публичные страницы каталогов.

| Вариант | Почему не используется |
|---|---|
| Yandex Travel Partner API | партнёрская модерация; лёгкий путь не даёт нужных отзывов |
| Travelpayouts / Hotellook | живой поиск отелей требует отдельного одобрения; данные кэшированные |
| RateHawk, Ostrovok B2B, Bronevik | договор, заявка или NDA |
| Amadeus Self-Service | тестовые данные ограничены и не соответствуют российскому рынку продукта |
| сбор цен на даты со страниц | цены загружаются отдельно и защищены; обход защиты запрещён |

Публичные страницы 101hotels содержат серверную микроразметку с названием, координатами, адресом, рейтингом,
изображениями и базовым `priceRange`. Ограниченный проход собирается без обхода robots.txt и защиты от ботов.

Наблюдаемый `priceRange` не меняется вместе с датами и является уровнем «от», а не доступным предложением.
Поэтому каталог и базовый уровень реальны, а сезонность цены проживания моделируется
([DEC-016 и DEC-029](../00_project/decision_log.md)).

Курируемый профиль содержит 408 объектов в семи направлениях и покрывает город, море и горы. Отдельный живой
проход может дать меньше строк из-за сетевых ошибок; это не меняет зафиксированный демонстрационный корпус.

## Авиатарифы: Ignav

Ignav предоставляет поиск аэропортов, one-way и round-trip тарифы и ссылки на бронирование. Адаптер хранит
наблюдённый ответ как snapshot и не повторяет платный запрос для тех же входов.

Критическая находка: параметр `market: "RU"` подавлял прямые российские маршруты. Без `market` возвращались
UTair, Ural Airlines и S7. Поэтому адаптер не отправляет этот параметр. Значение `price.status`
(`verified`/`unverified`) сохраняется вместе с тарифом.

Наличие покрытия не гарантирует доступность конкретного ключа или тарифа. Ошибка авторизации и отсутствие
маршрута — разные результаты и не должны смешиваться. Бюджет генерации ограничен 24 запросами тарифов
([DEC-028](../00_project/decision_log.md)).

## География

Основной API OpenStreetMap предназначен для редактирования, а не для массового чтения. Проект использует
ограниченные запросы Overpass, сохраняет ответы и импортирует геометрию в PostGIS один раз.

Практические выводы:

- POI достаточно получать как точки (`out center tags`); полная геометрия там только раздувает ответ;
- дороги, пешеходные пути и береговая линия импортируются с геометрией;
- Overpass может отвечать 429/504, когда общественный сервер занят; импорт уважает паузу и остаётся повторяемым;
- береговые линии Overpass уже пригодны для локального `ST_Distance`; собирать полигоны вручную не нужно;
- ohsome geometry на публичном endpoint отвечал 403, поэтому ohsome используется только для независимой
  проверки количества береговых объектов в двух bbox;
- ORS нужен только для времени автомобильного трансфера. Пешеходная среда рассчитывается локально по сети OSM;
- PostGIS-пересечение линии с буфером не заменяет проверку полного вхождения: целиком лежащие внутри пути
  измеряются целиком.

## Климат

Open-Meteo отдаёт климатические нормы и прогноз без ключа. Нормы сохраняются локально по направлению и месяцу,
прогноз имеет ограниченную свежесть. Бесплатный тариф предназначен для некоммерческого использования; перед
коммерческим запуском условия и тариф нужно пересмотреть.

## Отзывы

Бесплатного открытого источника текстов отзывов, пригодного для выбранного рынка, не найдено. Рейтинги каталога
не заменяют текст. Поэтому review-only риски не строятся, а Coverage сообщает причину отсутствия оценки.

## Локальные языковые модели

Проверки qwen3:8b и qwen3:14b подтвердили две вещи: JSON Schema проверяет форму, но не семантическую полноту, а
таймаут одной персоны может открыть circuit breaker и исказить статистику следующих. Поэтому результаты таких
прогонов нельзя превращать в единый «процент качества» без независимого запуска каждого входа.

Архитектурное следствие устойчиво независимо от конкретной модели:

- каждый вызов проверяется схемой;
- численные цели и арифметика остаются детерминированными;
- деградация видима вызывающей стороне;
- у каждой AI-задачи есть валидный fallback;
- качество проверяется на десяти персонах, а модель выбирается конфигурацией.
