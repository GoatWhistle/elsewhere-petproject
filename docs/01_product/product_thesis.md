# Продуктовый тезис

Источник правды по вопросу: что такое Elsewhere и чем он не является.

---

## Тезис

> Обычные travel-сервисы показывают отели. **Elsewhere строит возможные версии будущей поездки пользователя —
> целые поездки со стоимостью — и даёт изменить это будущее до того, как он на нём остановится.**

Пользователю не нужно заранее знать ни направление, ни отель. Он описывает опыт, который хочет прожить.
Elsewhere понимает, что важно *именно этому* человеку, строит несколько осмысленно разных вариантов будущего,
объясняет компромиссы, даёт отредактировать будущее, предсказывает значимые для него риски и выдаёт целую поездку.

## В чём сдвиг

| Сегодня | Elsewhere |
|---|---|
| Направление → Даты → Фильтры → Сотни отелей → Отзывы → Бронирование | Мечта → Futures → Симуляция → Прогноз → План |
| Работу по сопоставлению делает пользователь | Работу делает система и показывает свои рассуждения |
| Цена — это число | Цена — набор объяснённых компромиссов |
| Отзывы — обобщённые средние | Риски конкретны для предпочтений этого человека |
| Выбор делается вслепую | Каждый риск назван вместе с доказательством |

## Почему это может быть лучше, а не просто иначе

1. **Настоящий вход пользователя — это опыт, а не набор фильтров.** Фильтры заставляют переводить «спокойно,
   пешком, вкусно, без туристической ловушки» в приближения из галочек. Этот перевод теряет намерение.
2. **Выбор из трёх объяснённых вариантов лучше выбора из сотен** — при условии, что три действительно разные, а
   объяснение честное.
3. **Отзывы отвечают на «было ли это хорошо?», но не на «будет ли это хорошо *мне*?»** Средние 8,9 ничего не
   говорят чутко спящему о шуме с улицы после 23:00 со стороны дороги.
4. **Самое дорогое в решении о поездке — компромисс, и его никто не показывает.** «На 249 € дешевле, совпадение
   92% → 90%, вот три вещи, которые изменились» — информация, которой не даёт ни один сайт бронирования.

## Что должно быть правдой, чтобы тезис держался

- Travel DNA обязана ловить то, чего не ловят фильтры. Если она выродится в фильтры, продукт — оболочка.
- Futures обязаны действительно различаться по тем измерениям, которые важны пользователю.
- Совпадение обязано быть объяснимым и устойчивым, а не мнением модели, которое меняется при перезагрузке.
- Прогноз обязан опираться на доказательства. Одно уверенно ошибочное утверждение о риске уничтожает доверие ко всем.
- Симулятор обязан по-настоящему пересчитывать, а не переклеивать подписи.

Эти пять утверждений и есть настоящий продуктовый риск. Всё остальное — исполнение.

## Чем Elsewhere НЕ является

- Не клон Booking.com.
- Не чат, прикрученный сверху к поиску отелей.
- Не обычный планировщик маршрутов. Это ближайший сосед, и граница тонкая: разделяют их Travel DNA вместо
  фильтров, три по-настоящему разных будущих, симулятор, оценивающий каждый компромисс в деньгах, и риски,
  подкреплённые доказательствами. См. [trip_plan.md](trip_plan.md).
- Не набор несвязанных ИИ-функций.
- Не автономный исполнитель, совершающий необратимые действия без явного согласия.

## Что доказывает MVP

1. Пользователь описывает желаемый опыт.
2. Система строит структурированную Travel DNA.
3. Система возвращает несколько осмысленно разных Futures.
4. Пользователь меняет желаемое будущее.
5. Система пересчитывает и объясняет компромиссы.
6. Система показывает риски с доказательствами.
7. Пользователь уходит с целой поездкой — перелёт, проживание, трансферы, общая стоимость — и знает, какие числа
   наблюдаемые, а какие модельные.

Всё остальное вторично. См. [mvp_scope.md](mvp_scope.md).
