# Границы MVP

MVP должен доказать один тезис: человек может описать желаемый опыт, сравнить несколько разных вариантов
поездки, изменить выбранный вариант и понять цену компромисса до бронирования.

## Входит

| Возможность | Реализация |
|---|---|
| Мечта на естественном языке | обязательные город вылета, окно дат и состав вводятся рядом |
| Travel DNA | закрытая таксономия, происхождение, уверенность, ручная правка и версии |
| Futures | до трёх архетипов с порогами качества и объяснением неполного набора |
| Experience Match | детерминированный балл, contributions, coverage и confidence |
| Simulator | ползунки и свободная инструкция, новая версия Future и точная Delta |
| Forecast | четыре правила по географии и климату, доказательства и coverage |
| Каталог | 408 реальных объектов в семи курируемых направлениях |
| География | локальные признаки OSM/PostGIS |
| Климат | нормы и прогноз Open-Meteo |
| Авиатариф | Ignav в live-режиме, захваченные ответы в fixture-режиме |
| Цена проживания | наблюдаемая база объекта × модельная сезонность, маркировка `modeled` |
| Trip Plan | перелёт, проживание, логистика и общая оценка стоимости |
| Web UI | полный путь от Мечты до Forecast и Simulator |

## Не входит

- бронирование, заказ и оплата;
- программа поездки по дням;
- аккаунты и постоянный профиль путешественника;
- совместное редактирование и отправка спутнику;
- семьи, дети и требования доступности;
- мультивалютность — публичный контракт использует рубли;
- открытый поиск по всему миру;
- отзывы и выводы, требующие текста отзывов;
- Living Trip и наблюдение после принятия решения.

## Что обязано оставаться настоящим

Демонстрация не доказывает продуктовый тезис, если подменены:

- разбор Мечты или видимая деградация его fallback;
- применение жёстких ограничений;
- разнообразие Futures;
- разложение Match;
- арифметика Delta;
- связь Risk с измерением и доказательством;
- происхождение каждого компонента цены.

Fixture-режим допустим как стабильная реализация той же границы, если данные явно маркированы `fixture`.

## Критерий готовности

Один сквозной сценарий проходит через HTTP:

```text
session → Travel DNA → job → Futures → simulation → Forecast
```

Все ответы соответствуют OpenAPI, ограничения не нарушаются, суммы сходятся до минорной единицы, а отсутствие
данных видно пользователю. Это проверяет `spec/requests/phase_zero_spec.rb` вместе с contract- и persona-тестами.

## Следующее после MVP

Следующий объём появляется только вместе с новым подтверждённым требованием. Наиболее естественные направления:
постоянный профиль предпочтений, совместное решение и настоящий поставщик бронируемых остатков. Ни одно из них
не должно усложнять текущий путь заранее.
