# Публичный API

Контракт — **[openapi.yaml](openapi.yaml)** (OpenAPI 3.1). Этот файл источник правды; страница ниже — карта.

Обоснование решений: [api_principles.md](api_principles.md).
Почему он существует до реализации: [DEC-008](../00_project/decision_log.md) — работа идёт параллельно, поэтому
ограничение это интеграция, а не часы.

---

## Форма

| Этап пути | Эндпоинты |
|---|---|
| Мечта | `POST /planning-sessions` |
| Travel DNA | `GET /planning-sessions/{id}`, `PATCH …/travel-dna`, `POST …/clarifications` |
| Futures | `POST …/futures` → задача, `GET …/futures`, `GET /futures/{id}` |
| Симуляция | `POST /futures/{id}/simulations` → задача |
| Прогноз | `GET /futures/{id}/forecast`, `POST …/risks/{riskId}/mitigations/{mitigationId}` → задача |
| Асинхронность | `GET /jobs/{id}` |

10 путей, 11 операций, 33 схемы.

## Пять схем, на которых держится всё остальное

Замораживать в первую очередь их — именно ими делятся параллельные направления работ:

1. **`TravelDna` / `TravelDnaElement`** — граница между разбором Мечты и всем дальнейшим.
2. **`Future`** — единица, ради которой существует продукт, вместе с её `PriceBreakdown`.
3. **`ExperienceMatch` / `MatchContribution`** — контракт оценки.
4. **`RiskItem` / `Evidence`** — контракт прогноза.
5. **`Job`** — то, как возвращается всё медленное.

Шестого контракта в этом файле нет, потому что он внутренний: интерфейс **адаптера поставщика**
(см. [provider_adapters.md](provider_adapters.md), а также [DEC-005](../00_project/decision_log.md) о том, почему
у него две реализации).

## Что схема намеренно делает невозможным

- Совпадение без разложения.
- Риск без доказательства.
- Компонент цены, не говорящий, наблюдаемый он или модельный.
- Недостающие данные, молча оценённые как нейтральные.

Каждое из этого — угол, который реализация иначе срезала бы под давлением, и каждый тихо вернул бы продукт к тому,
что он призван заменить.
